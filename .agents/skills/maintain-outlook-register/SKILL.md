# 维护 Outlook 邮箱注册项目

## 必须遵守

- 修改仓库文件前，必须先检查当前分支最近一次 GitHub Actions 运行；若该运行对应当前分支的最新提交或该运行无任何错误，可直接作为基线，否则必须重新触发并等待运行完成。不得在缺少有效基线的情况下开始修改，因为需要从基线获取调试数据来辅助修改。
- `测试数据.txt` 第一行是 GitHub PAT；只读取当前工作流明确要求的后续输入行，不猜测、扩展或静默转换账号格式。PAT 仅用于触发和查询 Actions。
- PAT、生成的邮箱密码、refresh token、Cookie、会话 token、CapSolver key 不得输出、提交、写入 remote URL 或复制到其他文件；`测试数据.txt` 必须保持未跟踪。
- 只使用用户有权使用的自动化环境与密钥，不绕过 Microsoft 的地区限制、频率限制、设备限制、验证码或其他风控措施。需要人工完成的验证必须明确暂停并报告，不把风控页面当作选择器故障处理。
- 不覆盖或提交用户无关改动。截图、DOM、日志、下载产物和凭据不得提交。
- 以 Actions 的实时日志、URL、标题、截图和脱敏 DOM 为准，不凭选择器报错猜测页面状态。

## 修改循环

1. 检查 `git status`、当前分支、工作流、输入格式和相关源码，确认目标是注册 `@outlook.com` 并完成 OAuth2/IMAP 验证。
2. 修改前从 `测试数据.txt` 读取 PAT，触发当前分支的注册工作流并等待运行结束；敏感值只在进程内使用。
3. 检查每个账号矩阵 job 的结论；若 job 使用 `continue-on-error`，不得只看工作流顶层结论。
4. 注册失败时下载对应账号的失败日志和 evidence 产物，结合最后几个阶段的 URL、标题、截图和 DOM 确定失败点。产物只能下载到仓库外的临时目录，并在诊断结束后删除。
5. 先分类再处理：
   - 页面状态、选择器、iframe、弹窗、状态机或工作流错误：进行最小修改。
   - CapSolver 余额不足、密钥失效：停止修改，告知用户更新 `CAPSOLVER_API_KEY`。
   - 出现手机号验证：按约定停止，标记为外部阻塞，不尝试接码、绕过或伪造。
   - Microsoft 返回用户名不可用、服务不可用、设备或会话被限制：作为外部阻塞报告，不通过重试风暴、代理轮换、伪造设备信息或延长超时掩盖问题。
   - 出现需要人工识别的 CAPTCHA（CapSolver 无法求解）或其他交互式验证：保存脱敏证据并暂停，明确说明需要人工完成的步骤。
6. 修改后运行仓库已有的类型检查、构建和测试命令，复查 diff，确保没有凭据、注册结果或调试产物。
7. 仅提交并推送本次修改的文件，再次触发 Actions；重复检查、修改和验证，直到目标矩阵 job 成功或确认是外部阻塞。

## 注册流程约束

- 成功标准只有一个：账号已创建，并拿到可用的 `refresh_token`，且 OAuth2/IMAP 预检能连接 `outlook.live.com` 并读取收件箱。仅看到注册完成页或登录成功页不算成功。
- 域名优先 `@outlook.com`；Client ID 固定为 `9e5f94bc-e8a4-4e73-b8be-63364c29d753`；OAuth redirect URI 使用 `https://localhost`；scope 至少包含 `IMAP.AccessAsUser.All`、`SMTP.Send`、`offline_access`。
- 工作流输入是注册数量 `count`（默认 5），不是现成账号列表。账号用户名与密码在 job 内生成。
- 注册流程必须按实际页面状态分支处理用户名、密码、姓名生日、FunCaptcha/Turnstile、条款同意、登录态和 OAuth 授权页，不得假设顺序固定。
- 一旦检测到手机号/电话验证页面或电话输入框，立即停止该账号并标记外部阻塞，不得填写、跳过或绕过。
- 只在对应字段真实存在且可交互时填写内容；优先使用稳定属性、可访问名称和 URL 状态，避免只依赖易变化的文本、层级或语言。
- 生成的密码必须使用密码学安全随机源；不得在日志、截图、DOM 或错误消息中暴露密码与 refresh token。
- OAuth 授权在浏览器内自动完成：打开授权 URL、必要时登录、同意权限，拦截 `https://localhost` 回调中的 authorization code 再换取 refresh token。
- 各阶段和异常均保存配对的截图与脱敏 DOM。证据名称只使用账号索引和步骤名，不含邮箱、密码、验证码、token、Cookie。
- DOM 脱敏至少覆盖输入框值、邮箱、密码、授权码、token、Cookie 和查询参数；无法可靠脱敏的页面只保存经过裁剪的截图或结构化状态，不保存原始 DOM。

## 工作流约束

- 在矩阵启动前统一校验 `count`：必须是 1–20 的整数，格式错误立即终止。
- 矩阵只传账号索引，保持 `fail-fast: false`；并发度保守控制（默认 `max-parallel: 5`）。
- GitHub PAT、CapSolver API key 只能来自受控输入或 GitHub Secrets，不得硬编码。不得把完整注册资料放入矩阵 JSON、job 名称或普通日志。
- 每个账号独立上传脱敏结果和过程证据。成功结果格式：`邮箱----密码----client_id----refresh_token`。
- 为 Microsoft 页面请求设置有上限的超时和退避策略；不得高并发重复提交注册表单。
- 注册 job 即使允许继续执行，汇总 job 也必须保留每个账号的真实成功或失败状态，不能把缺少结果的账号统计为成功。手机号阻塞属于失败/外部阻塞，不得算成功。

## 成功标准

- 仓库已有的类型检查、构建命令全部通过。
- 每个目标账号 job 明确完成 `@outlook.com` 注册，并完成 OAuth2/IMAP 收信预检；外部阻塞必须单独标记，不能算作成功。
- 结果产物完整且最小化，日志、证据、提交和回复均未泄露个人资料或凭据。
- 未通过绕过 CAPTCHA、Microsoft 风控、频率限制、地区限制、手机验证或安全验证来获得成功结果。
